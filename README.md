# Mass Study · 깃허브판 안내 (v2: 로그인·초대코드·암호화·소개 페이지)

주소: **https://gridbox-007.github.io/Mass-study/**

## 이번에 바뀐 것

- **닉네임 + 비밀번호 로그인.** 로그인하지 않으면 서버의 데이터를 전혀 읽거나 쓸 수 없어요.
- **초대코드로 프로젝트 참여.** 프로젝트 목록에는 내가 참여한 것만 보여요. 코드를 모르는 사람은 이름조차 볼 수 없어요.
  - 초대 링크: `https://gridbox-007.github.io/Mass-study/?code=코드8자리`
- **조원 접속 표시.** 프로젝트 카드와 프로젝트 화면에 초록 점과 "n명 접속 중"이 보여요.
- **프로젝트 폴더.** 프로젝트 탭의 ‘새 폴더’로 프로젝트를 묶어요. 폴더는 나만 보는 정리용이에요.
- **암호화 저장.** 스터디·프로젝트·피드백·댓글·닉네임 내용은 서버 비밀 열쇠로 암호화(AES-256)하고 압축해서 저장해요.
- **권한을 데이터베이스가 직접 검사해요.**
  - 참여한 프로젝트의 작업물·피드백·댓글만 볼 수 있어요.
  - 처음 쓴 사람만 고치거나 지울 수 있어요.
- **저장 최적화.** 기본값과 같은 칸은 빼고 숫자는 1mm까지만 보내요. 몇 초 안에 똑같은 내용을 또 보내지 않고, 서버에서 한 번 더 압축해요.
- **검색 노출용 소개 페이지.** 처음 온 사람에게는 소개 페이지가 먼저 보여요. 이미 로그인한 사람, 초대 링크로 온 사람은 바로 편집기로 가요.

## A. 지금 쓰고 있는 사이트를 새 버전으로 바꾸기 (순서대로)

### 1단계 · Supabase 로그인 설정 (2분)

1. Supabase 대시보드 → 왼쪽 **Authentication** → **Sign In / Providers** (또는 **Providers**)
2. **Email**이 켜져 있는지 확인해요.
3. **Confirm email**을 **끄고** 저장해요.
   - 가짜 이메일(닉네임으로 만든 주소)을 쓰기 때문에, 이걸 켜 두면 가입이 끝나지 않아요.
4. **Allow new users to sign up**이 켜져 있는지 확인해요.

### 2단계 · 데이터베이스 바꾸기 (5분)

1. **SQL Editor → New query**에서 먼저 백업 한 줄을 실행해요.
   ```sql
   create table if not exists ms_docs_backup_v1 as table ms_docs;
   ```
2. 새 `supabase-setup.sql` 내용을 **전부** 붙여넣고 **Run** 해요.
   - 여러 번 실행해도 괜찮아요.
   - 처음 실행할 때 기존 데이터가 암호화된 형태로 옮겨져요.
   - 기존 프로젝트와 참여자는 그대로 남고, 프로젝트마다 초대코드가 새로 생겨요.
3. 잘 옮겨졌는지 확인하려면 아래를 실행해요. 두 번째 숫자가 `0`이면 평문으로 남은 게 없다는 뜻이에요.
   ```sql
   select count(*), count(*) filter (where data is not null) from ms_docs;
   ```
4. 일주일쯤 잘 쓴 뒤에는 백업을 지워도 돼요: `drop table ms_docs_backup_v1;`

### 3단계 · GitHub 파일 올리기 (5분)

저장소 `Mass-study` → **Add file → Upload files**로 아래 파일을 올리고 **Commit changes**를 눌러요. 같은 이름의 파일은 덮어써요.

| 파일 | 하는 일 |
|---|---|
| `index.html` | 사이트 본체 + 소개 페이지 (Supabase 연결값은 이미 들어 있어요) |
| `robots.txt`, `sitemap.xml` | 검색엔진 안내 |
| `manifest.webmanifest`, `icon.png` | 웹사이트 아이콘 |
| `og.jpg` | 카카오톡·검색 결과 미리보기 이미지 |
| `study.jpg`, `sketch.jpg`, `project.jpg`, `feedback.jpg` | 소개 페이지 화면 이미지 |
| `supabase-setup.sql`, `README.md` | 설정 · 이 안내 |

`.github/workflows/keepalive.yml`도 새 내용으로 바꿔요. 연필 ✏️ 버튼으로 전체를 지우고 새 내용을 붙여넣으면 돼요. 예전 것은 이제 작동하지 않아요.

### 4단계 · 조원들에게 알려 주기

- 사이트를 열고 **매스 스터디 시작하기 → 처음이에요**를 눌러 닉네임과 비밀번호(8자 이상)를 정해요.
- **예전 작업 옮기기:**
  - 예전에 쓰던 기기, 같은 브라우저에서 가입하면 그 기기에 있던 작업이 새 계정으로 자동으로 옮겨져요.
  - 다른 기기라면, 저장해 둔 **예전 열쇠 링크**를 그 기기에서 한 번 연 다음 가입하세요.
- **같은 닉네임은 하나만 만들 수 있어요.** 닉네임이 로그인 아이디예요.
- 프로젝트를 만든 사람은 프로젝트 화면 위쪽의 **초대코드**나 **초대 링크 복사**로 조원을 불러요. 기존 참여자는 그대로 남아 있어요.

### 비밀번호를 잊었을 때 (관리자가 SQL Editor에서)

```sql
update auth.users set encrypted_password = extensions.crypt('새비밀번호8자이상', extensions.gen_salt('bf'))
where id = (select auth_id from public.ms_users where nick = '닉네임');
```

## B. 검색엔진 등록 (직접 해야 하는 일)

### Google Search Console

1. search.google.com/search-console → **속성 추가** → **URL 접두어**에 `https://gridbox-007.github.io/Mass-study/`
2. 확인 방법에서 **HTML 태그**를 골라 `content="…"` 안의 코드만 복사해요.
3. GitHub에서 `index.html`을 연필 ✏️로 열어요. `google-site-verification` 줄의 `구글에서-받은-코드`를 그 코드로 바꾸고 Commit 해요.
4. 1~2분 뒤 Search Console에서 **확인**을 눌러요.
5. 왼쪽 **Sitemaps**에 `sitemap.xml`을 넣고 **제출**해요.
6. **URL 검사**에 주소를 넣고 **색인 생성 요청**을 하면 더 빨리 잡혀요.

### 네이버 서치어드바이저

1. searchadvisor.naver.com → **웹마스터 도구** → 사이트 등록에 `https://gridbox-007.github.io/Mass-study/`
2. **HTML 태그** 방식을 골라 코드를 `naver-site-verification` 줄에 넣고 Commit → **소유확인**
3. **요청 → 사이트맵 제출**에 `https://gridbox-007.github.io/Mass-study/sitemap.xml`
4. **검증 → robots.txt**와 **웹페이지 최적화**로 확인해요.

> **robots.txt 참고:** 검색엔진은 `https://gridbox-007.github.io/robots.txt`(주소 맨 앞)만 읽어요.
> 저장소 안의 `robots.txt`는 `gridbox-007.github.io`라는 이름의 저장소를 따로 만들지 않는 한 쓰이지 않아요.
> 그래도 괜찮아요. 맨 앞에 robots.txt가 없으면 "모두 허용"으로 읽고, 사이트맵은 위처럼 직접 제출하면 돼요.

검색 결과에 나오기까지 보통 며칠에서 몇 주 걸려요.

### 검색에 나오는 것과 안 나오는 것

- **나오는 것:** 소개 페이지 한 곳뿐이에요. 사이트맵에도 이 주소 하나만 있어요.
- **안 나오는 것:** 내 작업, 프로젝트, 작업물, 피드백.
  - 로그인한 뒤 서버 함수로만 받아 오고, 따로 주소가 없어서 검색엔진이 볼 수 없어요.
  - 예전 열쇠 링크(`?key=`)는 열자마자 주소에서 지워져요.
- 사이트 안에 넣은 Supabase 키는 공개용(Publishable) 키뿐이에요. 비밀 키는 어디에도 넣지 않았어요.

## 보안 정리 (무엇이 어떻게 보호되나요)

| 항목 | 보호 방법 |
|---|---|
| 로그인 안 한 사람 | 모든 서버 함수가 로그인 확인부터 해요. 표에는 아무도 직접 닿을 수 없어요 |
| 내 작업 | 나만 읽고 써요 |
| 프로젝트 | 참여자만 보고, 이름은 만든 사람만 바꿔요. 참여·나가기는 서버 함수로만 해요 |
| 공유한 작업물 | 그 프로젝트 참여자만 봐요. 참여한 프로젝트에만 올릴 수 있어요 |
| 피드백 | 쓴 사람, 받은 작업물 주인, 그 작업물이 올라간 프로젝트 참여자만 봐요 |
| 댓글 | 작업물 주인과 그 프로젝트 참여자만 보고 쓰고, 작성자는 서버가 정해서 바꿔치기할 수 없어요 |
| 고치기·지우기 | 처음 쓴 사람만 할 수 있어요. 함께 쓰는 레퍼런스 폴더 정리(`meta/`)만 예외예요 |
| 초대코드 추측 | 8자리(약 1조 가지)이고, 한 사람이 한 시간에 20번까지만 시도할 수 있어요 |
| 저장 내용 | AES-256으로 암호화하고 압축해요. 열쇠는 어떤 사용자도 읽을 수 없는 표에 있어요 |

**알아둘 점**
- 암호화는 데이터베이스가 새어 나가거나 API로 들여다보는 경우를 막아요. Supabase 프로젝트 관리자(나)는 SQL Editor로 열쇠에 닿을 수 있어요.
- 아래 항목은 암호화하지 않아요. 내용은 들어 있지 않아요.
  - 경로(아이디)
  - 저장 시각
  - 참여자 목록 표
  - 공유 작업물이 어느 프로젝트에 올라가 있는지
- 레퍼런스 사진은 길고 무작위인 주소로 저장돼요. 올리는 건 로그인한 사람만 할 수 있지만, 주소를 아는 사람은 사진을 볼 수 있어요.

## 무료 한도 (Supabase Free)

- 데이터베이스 500MB, 사진 저장 1GB. 넘으면 요금이 나가는 게 아니라 기능이 멈춰요.
- 7일 동안 아무도 안 쓰면 일시정지돼요. `keepalive.yml`이 3일마다 깨워요.
  - 60일간 저장소에 변화가 없으면 GitHub가 자동 실행을 멈추고 메일을 보내요. 메일이 오면 **Actions → Enable workflow**를 눌러요.

## 안 될 때

| 증상 | 확인할 것 |
|---|---|
| "데이터베이스 설정이 아직 새 버전이 아니에요" | 2단계 SQL을 끝까지 Run 했는지 |
| 가입했는데 "Confirm email을 꺼 주세요" | 1단계 3번 |
| "이미 있는 닉네임이에요" | 다른 닉네임으로 가입하거나, 그 닉네임으로 로그인 |
| 예전 작업이 안 보여요 | 예전 열쇠 링크를 연 상태에서 가입했는지 (이미 가입했다면 관리자에게 알려 주세요) |
| 초대코드가 안 맞아요 | 코드를 새로 만들었는지 프로젝트 만든 사람에게 확인 |
| keepalive가 빨간 X | 2단계 SQL(`ms_ping` 포함)을 다시 Run |
